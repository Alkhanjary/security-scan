Three scan modes, one report

Point it at a folder, a URL, or a host/CIDR — it works out what to do from what you give it.

Code

Hardcoded secrets and API keys, dangerous calls (eval, os.system, shell=True), SQL injection, XSS sinks, insecure deserialization, weak crypto and infra misconfiguration.

Web

Missing security headers (HSTS, CSP, X-Frame-Options), insecure cookie flags, TLS certificate and protocol issues, reflected XSS and error-based SQL injection via a same-origin crawl.

Network

Open ports, risky exposed services (FTP, Telnet, RDP, VNC) and outdated-looking service banners, across a single host or a whole /24 subnet.

AI layer

Every finding gets a true/false-positive verdict with a reason, plus a pass for what the rules missed and a plain-language risk summary. The deterministic scan stays the source of truth.

Every finding explains itself

No bare rule IDs to go and look up. Each one carries the line that triggered it, what could actually go wrong, the specific fix, and — with the AI layer on — whether it's real and why.

Findings in test fixtures are separated from application code automatically, so your sample passwords stop drowning out the genuine ones.
